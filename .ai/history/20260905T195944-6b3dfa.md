# Confirm SIDE lighting mode power-cycle retention

- Change ID: `20260905T195944-6b3dfa`
- 作成日時: 2026-09-05 19:59:44 +0900

## 目的

SIDE-KEYBOARDのmode 2・単色HSV設定がUSB電源断を越えて保持されるかを、
Serial `592B14678182`の1台だけで確認し、runtime高頻度writeの安全性を判断する。

## 実施内容

- mode 5から、すでに保存済みのmode 2・単色赤へ公式response-derived sequenceで1回切り替えた。
- 即時readback `01 00 02 04 02 00 01 FF 00 FF FF`を記録した。
- ユーザーが対象deviceだけを約10秒USBから外し、公式app/OverCUE操作なしで再接続した。
- 再接続直後から全key赤呼吸が再開することを目視確認した。
- 再接続後はread-only `06 0A` / `06 13`を各1回だけ送り、configとRGB chunkの
  電源断前後byte一致を確認した。setter/retry/他Serialへの送信はない。
- 既存のruntime integration gateを、persistent mode writeをPlay/Pause駆動へ使わない
  Decisionで置換した。

## 検証

- Visual: 電源断・再接続直後も全keyが単色赤で呼吸。
- `06 0A`: offsets 5...15が電源断前後でbyte一致。
- `06 13`: first RGB chunkが電源断前後でbyte一致。
- 前commit `d57d2f0`で35 unit tests / 405 Core checks / Universal Binary / codesignを確認済み。
  今回はdocumentation/AALのみの追加で、同結果を新規実行したとは扱わない。

## 残課題

- storage medium（flash/EEPROM）、commit timing、write enduranceは未特定。
- runtime同期には既知のpersistent setterではなく、RAM-only command/transportの証拠が必要。
- deviceはmode 2・単色赤のまま。自動rollbackは行っていない。
