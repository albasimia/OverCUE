# Generic HID runtimeとinput backendを修復

- Change ID: `20260903T025320-7786f8`
- 作成日時: 2026-09-03 02:53:20 +0900

## 目的

登録済みGeneric HIDのnative入力は抑止できてもAction runtimeへraw eventが届かず、rekordbox操作が発火しない問題を実機ログで特定して修正する。複数input backendの一方が失敗したとき、正常なbackendまで停止する結合と、Devices Identify後にcontroller input設定がOFFへ残る経路も閉じる。

## 実施内容

- Action runtimeのIOHID openを`SeizeDevice`からsharedへ変更した。keyboard-class interfaceがmanager open後にmatchした場合、open自体はsuccessでも遅延exclusive claimが失敗しinput callbackが来ない実機挙動へ対応した。
- opt-inの`OVERCUE_GENERIC_HID_DIAGNOSTICS=1`ログを追加し、session / Logical Device / Preset / usage / mapping hit / commandId / shortcut / frontmost判定を追跡可能にした。
- ACK05 CLIとGeneric HID runtimeを独立backend化し、一方の起動失敗・終了で他方を停止しないようにした。部分稼働時はdegraded statusを表示する。
- アプリ起動CLIへ`--parent-pid`を渡し、親GUI消失時にCLIが終了してexclusive ACK05 claimを残さないようにした。
- Devices Identify / Rebindのruntime停止を一時停止APIへ分離し、controller inputのUserDefaultsをOFFとして保存しないようにした。
- 実機では登録済みSerial `3F8701678182`の3 interfaceを1 sessionへ統合し、Key2→`300b`→`F`、Key3→`300a`→`D`、Knob Right→`305b`→`shift+E`のAction解決とrekordbox最前面時のCGEvent送信を確認した。
- 同時接続中の2台目SIDE-KEYBOARDはSerial `592B14678182`で、現行configには未登録であることを確認した。未登録個体は従来どおりfail-openする。
- shared runtime / backend isolation / Identify semanticsをDecision、project、next、current specへ反映した。
