# Generic HID native suppressionを実機診断

- Change ID: `20260903T022736-c5bb82`
- 作成日時: 2026-09-03 02:27:36 +0900

## 目的

登録済みSIDE-KEYBOARDのnative Keypad / Volume / Mute入力が1件も抑止されない原因を、Suppressor起動、raw IOHID callback、CGEventTap callback、時刻、keyCode / NX key type、権限の実機ログから特定する。原因特定前に相関待機やfilterを推測変更しない。

## 実施内容

- 初回起動ではUserDefaults `ack05BridgeEnabled=0`を確認した。ログは`stop requested`だけで、`GenericHIDNativeEventSuppressor.start()`、IOHID callback、CGEventTap callbackはいずれも実行されなかった。controller inputを有効化して同じbinaryを再起動するとSuppressorが起動し、登録binding 1件から3 IOHID interfaceをmatchした。
- Input Monitoring / Accessibility preflight、IOHID open、run-loop生存、event tap enable、raw usage/report/value、CGEvent type/keyCode/systemDefined data、相関drop/passを記録するopt-in診断ログを追加した。`OVERCUE_HID_SUPPRESSION_DIAGNOSTICS=1`のときだけstderrへ出力する。
- Key1〜4はUsage `0x59〜0x5C`からmacOS keyCode `83〜86`へ対応し、press / releaseともdropされた。
- Knob Right / Left / PushはConsumer `0xE9 / 0xEA / 0xE2`から`systemDefined` subtype 8、NX key type `0 / 1 / 7`へ対応し、press / releaseともdropされた。
- raw IOHIDからCGEventまでの差は約0.3〜5msで既存8ms待機内だったため、待機時間は変更しなかった。無関係なsubtype 7 eventはfail-openした。
- controller input全体を制御する設定が英語・簡体字中国語でACK05専用に見えていたため、Controller Input表記へ修正した。OFF時にnative入力を通す既存semanticsは維持した。
- 実機証拠をAAL project / nextとcurrent specへ反映した。
