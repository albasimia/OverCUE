# Restore Generic HID delivery and connected interfaces after restart

## 目的

remote最新`adda014`から開始。ユーザー提示の`side-20260905-003037.log`抜粋では初回3台正常、
restart後69964.620512 start→69964.667380 open success以降match/metadata/state/inputなし。
抑止側はE9/EA/E2を受信。logファイル全体は今回取得しておらず、引用はユーザー提供分。
`adda014`の約750ms遅延解消はユーザー実機確認済みとの報告。今回はrestartのみを修正する。

## 実施内容

- Apple公開`IOHIDManager.c`でCloseがUnscheduleを呼び、OpenはScheduleしないことを確認。
  旧実装はinit時のみSchedule、stopでClose＋全live state破棄、startでOpenのみだった。
  初回と違いrestartは監視解除されたままで、既接続match通知への暗黙依存もあった。
- 各start成功後にmain runloopへ再Scheduleし、IOHIDManagerCopyDevices snapshotを明示登録。
  snapshot/matchは共通registerMatchedInterface→既存identity/grouping→preload→state refreshへ集約。
  既存interface set / session key / ready catalogを再利用して二重生成を防ぐ。
- config reloadでもsnapshotを再取得。snapshot未取得・metadata失敗は入力内でretryせず、
  lifecycle/config/reconnect/next startへ委ねる。Open失敗時は部分openをCloseしてcleanup。
- stopではClose前にisOpen=falseとし、停止中callbackの再登録/入力を拒否。catalog/session/handle全破棄を維持。
- snapshot件数/登録source/capture begin/captured/endのlazy診断を追加。
- GenericHIDShortcutCaptureModel→ShortcutSettingsModel→OverCUECLIRuntime→同じruntime captureの境界を確認。
  Learnのsave target/persistence、Preset/Group Preset、identity、ACK05、native抑止8ms、UIは変更なし。
  callbackのcookie lookup/ambiguity safetyと入力時非列挙を維持。
