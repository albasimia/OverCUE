# Preload Generic HID interface metadata outside input callbacks

- Change ID: `20260905T001653-45d64b`
- 作成日時: 2026-09-05 00:16:53 +0900

## 目的

`codex/performance-4deck` remote HEAD `9e0ee1c`から開始（pull --ff-onlyで最新確認）。
ユーザー提供のSIDE実機診断でRightのcallback→inputが約764ms、Leftが約750ms、
Clickも同程度停止し、後続入力がburstする。routingとrekordbox shortcutsは正常との報告。
初回descriptorごとの同期全element走査を入力callbackから除去する。

## 実施内容

- 従来はcookie cache miss→descriptor構築→全element列挙→各collection path再構築→重複数算出。
  warm cacheでは初回usageごとの停止が残る構造だった。
- interface match時、全elementのdescriptor/cookie/relativeをsnapshotし、descriptor出現数を一括集計。
  入力はinterface/cookie lookup→normalize→既存Action route。入力でbinding propertyを再取得せず、
  match/remove/config reloadで既存ロジックが解決したsession registryを参照する。
- 重複descriptorのcount >1は従来どおりunpersistable。report/pathを含む等価性を維持。
  不正な重複cookieはlookup不可としてfail-closed。cookieは永続化しない。
- 既存main-runloop IOHID owner上でready前に同期preload。Apple公開実装の列挙はdevice/element内部も更新するため、
  根拠なく別threadへlive IOHID objectを共有しない。新しいthreading ownerやDecisionは導入せず、
  既存cache境界Decision `20260904T084205-a76908`の範囲でperformance bugを修正。
- ready catalogはconfig reloadで再利用。nil/empty列挙は未readyのままmatch/config reload/restartで再試行。
  入力中retry・sleep・replayなし。removeで該当interfaceのcatalog/handleだけ解放、stop/startで全破棄。
- lazy診断を維持しmetadata preparing/ready/failed/missを追加。callback/input時刻で修正後測定可能。
- identity、Preset、Group Preset、mapping scope、Unified Learn、ACK05、command ID、native suppressionの
  8ms仕様に変更なし。Deck2 Right/Clickの未割当は補完せず、実ユーザーconfigにも触れていない。
