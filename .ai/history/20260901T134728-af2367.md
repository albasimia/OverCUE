## 目的

commit `795e70b fix: serialize runtime config state`で修正した2件のP1をmacOSローカルで再レビューし、default / non-default Profile間のruntime target分離と、GUI / CLI間の`config.json` SSOTが実際に閉じていることを確認する。新機能やDevices UIへは進まず、見つかった競合だけを局所修正して自動検証とUniversal Binary app生成まで完了する。

## 実施内容

### レビューで追加確認した問題

1. `795e70b`の`Darwin.flock`呼び出しはSwift 6 on macOSで同名の`flock`構造体へ解決され、`swift build`が失敗した。
2. GUI target未確定時のglobal control fallbackにより、default Profile deviceが未接続または切断済みでnon-default deviceだけが存在すると、そのdeviceへcontrolが届き得た。切断targetもGUIへ明示的に解放されていなかった。
3. 通常更新はlock内read-modify-writeになったが、version 1〜8 migrationはlock外で読んだ旧snapshotをlock取得後に書いており、別processが先にmigrationと更新を終えた直後を巻き戻せた。
4. 同一Groupのruntime reloadはmappingを差し替えるだけで、旧mappingのhold / key repeat / waveform drag状態が残り得た。またPhysical Binding変更後のProfileを再評価していなかった。
5. default GUIのinput表示はdeviceをfilterしておらず、non-default deviceのキー／ダイヤル表示が混入し得た。

### 修正

- C symbol `flock(2)`を明示するshimへ変更し、`EINTR`時はlock / unlockを再試行する。stableな`config.json.lock`をlockし、`config.json`自体はatomic replaceする構造を維持した。
- Coreへ`OverCUERuntimeTargetPolicy`を追加し、default Profile statusだけをtargetへ採用する。CLIは切断statusをpublishし、GUIは対象device切断時にtargetとinput highlightを解放し、再接続statusで新session IDへ更新する。
- default GUI runtime controlはProfile名付きdevice scopeだけを使用する。live default targetがなければ送信せず、global fallbackを禁止した。CLI reload後にPhysical Binding / Logical Device / Profileを再解決し、通知対象Profileと一致しなければcontrolを拒否する。
- CLIの通常key / dial処理がruntime statusを先にpublishする既存修正を確認し、GUI input notificationは現在のdefault target deviceだけを表示するようにした。
- `migrateCurrentIfNeeded`を追加し、migration対象versionの再読込、backup、current config書込を同一lock内で行う。別processが既にcurrentへ移行済みならmigration closureを実行せず、最新stateを採用する。
- 同一Group runtime reloadでもresolverをresetし、hold / key repeat / waveform dragを終了して、最新mapping / Deck / waveform位置へ更新する。
- 3-way merge、dictionary entry変更／削除、Profile / Group / Logical Device独立merge、GUI Deck + CLI Mode、missing / unsupported config、migration競合、runtime target切断／再接続をCore checksへ追加した。
