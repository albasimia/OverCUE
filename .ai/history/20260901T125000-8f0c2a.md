# runtime targetとconfig永続化の追加レビューゲートを修正

- Change ID: `20260901T125000-8f0c2a`
- 作成日時: 2026-09-01 12:50:00 +0900
- レビュー対象: `e822d548dedd07156e57a8aba8665a4b291796c6`
- 状態: 実装修正済み / macOSローカル検証待ち

## 背景

commit `e822d54`でcommit `3a81b4e`に対する4件の複数deviceレビューゲートを閉じた後、追加レビューで2件のP1を確認した。

1. `ShortcutSettingsModel.applyRuntimeStatus()`がnon-default Profileのstatusでもruntime device metadataを更新してからdefault Profile表示だけを弾いていたため、default Profile用GUIのcontrol targetがnon-default deviceへ奪われ、その後のGUI controlが送信不能になり得た。また、CLIは通常のキー／ダイヤル操作ではruntime statusをpublishしていなかったため、AAL上の「最後に操作したdevice」は実際には「最後にstatusを出したdevice」だった。
2. GUIとCLIが`config.json`を別々のin-memory `OverCUEConfiguration`として保持し、それぞれ全体snapshotを書き戻していた。GUIでDeck変更後にCLIが古いsnapshotからModeを保存する、またはCLIのMode / waveform変更後にGUIが別設定を保存することで、相手processの変更を後勝ちで消す経路があった。

Generic HID / Devices UIで永続設定項目が増える前に、この2件を追加ゲートとして解消する。

## 実施内容

### Runtime target

- default Profile用GUIはsource Profileが`configuration.defaultProfile`と一致するruntime statusだけをcontrol targetとして採用するよう変更した。
- non-default Profileのstatusはdefault UIの`runtimeDeviceID` / `runtimeLogicalDeviceID` / `runtimeProfileName`を更新しない。
- CLIは通常のACK05キー入力およびダイヤル入力時にも現在deviceのruntime statusをpublishする。
- これによりdefault Profile用GUIのtargetは、default Profileを使うACK05のうち実際に操作されたdeviceへ追従する。

### config.jsonのprocess間SSOT

- `Sources/OverCUECore/OverCUEConfigurationPersistence.swift`を追加した。
- `OverCUEConfigurationFileStore`が`config.json.lock`を`flock`で排他取得し、version 9 configを最新read-modify-writeする共通永続化経路を提供する。
- `OverCUEConfigurationMerger`を追加し、GUIは「最後に同期したbaseline / GUI local state / 最新disk state」の3-way mergeで保存する。
- Profile / Group内はfield単位、key / chord / dial mapはentry単位でGUI差分だけをlatestへ適用し、GUIが変更していないCLI側更新を保持する。
- CLIのMode保存とwaveform位置保存はlock取得後の最新configへ対象fieldだけを書き込む。
- GUI runtime controlを受けたCLIは処理直前に最新configをreloadし、全Profile / GroupのAction mappingを再構築してからGroup / Mode / Deckを解決する。
- 同一GroupをGUIから再指定した場合もreload後のmappingへ差し替える。
