## 目的

`feat: isolate physical HID device state`の実装を、AALで採用済みのPhysical Device / Logical Device分離と複数同型デバイス運用の前提に照らしてレビューし、Generic HID / Devices UIへ進む前に解消すべき修正ゲートを正本へ記録する。

## レビュー結果

### P1 — live session identityがSerial重複時に衝突する

`HIDPhysicalDeviceDescriptor.sessionIdentifier`が、Serialが存在する場合にpersistent identifierをそのまま返し、`PerDeviceACK05ReportRouter`がそれをcontroller store keyとして使っている。このため、同型2台が同じSerial文字列を返した場合、InputActionResolver、Cue hold、Jump repeat、Group / Deck、ダイヤル、波形ドラッグ等が同じcontrollerへ再合流する。

修正要求:

- live session identityとpersistent binding identityを分離する。
- controller stateは接続インスタンス単位で必ず分離する。
- Serialは永続binding候補としてのみ使用する。
- 同時接続中に同一VID / PID / Serialが複数存在する場合は自動bindingを確定せず、曖昧状態としてIdentify / Rebind可能にする。
- 同一Serialの2descriptorでもstateが独立するCore checkを追加する。

### P1 — Runtime Status / Controlにdevice scopeがない

複数`MouseBridgeController`が同じDistributed Notificationを購読し、Runtime Status / Controlにはmode / groupしか含まれていない。GUI側はsource device / profileを識別できないままruntime statusを受け、`defaultProfile`へ保存する経路がある。これでは一方のACK05の状態変更が別controllerまたは無関係なProfileへ波及し得る。

修正要求:

- Runtime Status / Controlへdevice scopeを持たせる。
- 特定device操作とglobal操作を曖昧にしない。
- CLI由来statusを受けただけでGUIが`defaultProfile`へ無条件保存しない。
- sourceと保存対象Logical Device / Profileを一致させる。
- single ACK05時の従来UXは維持する。

### P1 — legacy `location:`がpersistent bindingとして復活する

version 9 migrationではlegacy `location:XXXXXXXX`を`lastKnownLocationID`に加えて`legacyDeviceIdentifier`へも保存している。新descriptorも現在のLocationIDをlegacy identifierへ含めるため、同じUSB portへ別個体を挿しただけで旧Logical Deviceへpersistent matchし得る。これは「LocationIDはRebind hintのみ」という採用済みdecisionと矛盾する。

修正要求:

- legacy IDが`location:`の場合は`lastKnownLocationID`だけへ移し、persistent match対象の`legacyDeviceIdentifier`へ入れない。
- `PhysicalDeviceUniqueID` / `DeviceAddress`等を後方互換で扱う場合は`location:`と分岐する。
- 同じLocationIDの別個体が自動bindingされないCore checkを追加する。

### P2 — ACK05 captureで複数deviceの入力を混在できる

`ACK05InputMonitor`内部ではprevious key stateをdevice別に持つが、上位callbackへdevice IDを渡していない。`ShortcutSettingsModel`は単一の`capturedKeyOrder`を持つため、ACK05 AのK7とACK05 BのK1を1つの`K7+K1`コードとして誤認できる。

修正要求:

- monitor callbackにsource device IDを含める。
- Capture開始後の最初の入力deviceをcapture sourceとして固定し、完了 / キャンセルまで他device入力を無視する。
- source device切断時の挙動を定義する。
- 2台の入力を1コードへ混在させないcheckを追加する。
