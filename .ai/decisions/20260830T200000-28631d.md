# Deck targetを既存GroupとAction Layerへ統合する

- Change ID: `20260830T200000-28631d`
- 状態: 採用

## 背景

従来は標準ActionがDeck 1のcommandIdへ直接結び付き、Deck 2だけがDefaultKeyMappingに`rekordbox:31xx`として直書きされていた。この方法でDeck 3/4を追加すると、同じ操作定義と設定がDeckごとに複製される。また既にGroupごとのmodeと波形位置があり、別のDeck modeを追加すると状態管理が二重になる。

## 決定

- 各`OverCUEGroupMapping`へ`rekordboxDeck`（1〜4）を持たせる。
- PERFORMANCEの標準Actionは`ActionID + RekordboxDeck`からcommandIdへ解決する。
- ActionごとにDeck共通のcommand suffixだけを定義し、Deck prefixを解決時に付与する。
- Generic `rekordbox:<commandId>`はユーザーの明示指定として、そのまま使用する。
- EXPORTでは`rekordboxDeck`を操作解決に使わず、従来のDeck 1 commandIdを使用する。
- Group別`waveformPosition`はDeck targetと独立したまま同じGroup設定に保持する。

## 理由

- 既存の4 Groupがmode、入力マップ、波形位置の切り替え単位として既に成立している。
- Actionの意味と対象Deckを分離すれば、Deck別ActionやDefaultKeyMappingのコピペを避けられる。
- Generic commandIdを変換しないことで、ユーザーがrekordbox固有機能を直接指定する逃げ道と後方互換性を保てる。
- EXPORTにDeck選択を適用しないことで、既存Group 3の意味を維持できる。

## 影響

- config version 8以降ではGroupごとに`rekordboxDeck`を保存する。
- 旧既定Group 2はDeck 2 + 標準Actionへmigrationする。
- Shortcut GUIとBridgeはGroup変更時にmode、Deck、波形位置をまとめて復元する。
- 新しいDeck依存標準Actionはsuffixを一箇所追加すればDeck 1〜4へ展開される。
- Deck 4の実データが現行Presetにないため、`33xx`規則は実機確認まで未検証事項として残す。

## 代替案

- Deck別Action IDを追加する案: ActionとGUI項目が4倍に増え、Single Source of Truthを失うため不採用。
- Deck 2〜4をすべてGeneric commandIdでDefaultKeyMappingへ直書きする案: 既存の二重管理を拡大するため不採用。
- Groupとは別にDeck modeを追加する案: 切り替え状態とUIが二重になるため不採用。
