# Physical DeviceとLogical Deviceを分離してGeneric HIDへ拡張する

- Change ID: `20260901T110700-c8f4b1`
- 状態: 採用

## 背景

OverCUEはACK05 1台から始まったが、標準3Deck物理リグではACK05と小型Generic HIDをDeckごとに複数台同時利用する。Generic HIDをglobal keyboard eventへ変換してから扱うと、Device AのF13とDevice BのF13を区別できず、同型デバイスを同じshortcut mapで運用できない。またUSB port / locationを恒久IDにすると、hubやport変更だけで設定が壊れる。

## 決定

- Physical HID DeviceとLogical Deviceを別概念にする。
- Profileおよび将来のParent PresetはPhysical DeviceではなくLogical Deviceを参照する。
- Generic HID入力は可能な限りIOHIDのdevice sourceを保持した状態で取得し、`Device + Input`をbinding単位にする。
- ACK05はOfficial / First-class deviceとして専用UIと保証対象を維持する。
- Generic HIDはAdvanced / Best-effortとし、Keyboard / Consumer Control等の標準的なHID入力を主対象にする。
- 未登録Generic HIDは受動的に検出しても自動登録しない。登録はDevices → Add Generic Device → Identify/Learnでユーザーが明示的に行う。
- 物理識別は固有Serialを最優先する。VID/PIDだけで同型個体を区別したことにしない。
- USB topology / locationは再接続時の候補ヒントには使えるが、永続的なLogical Device IDにはしない。
- 一意に再bindingできない場合は「対象Logical Deviceを操作してください」という物理Identify / Rebindで解決する。
- Generic HIDの具体製品画像・型番をデータモデルや主要UIの前提にしない。Koolertron系デバイスは検証対象の一例として扱う。
- Learnは「物理入力をOverCUE Actionへ結び付ける」抽象操作とし、将来ほかのInput Adapterを追加できる余地を残す。

## 理由

- 同型デバイス複数台でも同じshortcut mapを再利用できる。
- ハードウェア交換時にLogical DeviceへRebindするだけでProfileを維持できる。
- USB hubやport変更をユーザー設定破損へ直結させずに済む。
- ACK05の公式サポート品質とGeneric HIDの拡張性を混同しない。
- 特定の購入機材へOverCUE全体をロックインしない。

## 影響

- 入力層はdevice identityをAction Layerへ到達するまで保持する必要がある。
- configにはLogical Device、Physical Binding、Profile Assignmentの永続化が必要になる。
- Devices UIにIdentify、Rename、Profile assignment、Rebind、Forget等が必要になる。
- 複数ACK05の入力状態も同じく物理device単位へ分離する方向で実装する。

## 代替案

- 各Generic HIDへ別キーコードを設定してglobal keyboard eventだけで区別する案: 9/6向け暫定回避には使えるが、正式設計ではハードウェア設定へ依存しすぎるため不採用。
- VID/PID + USB locationを恒久IDにする案: hub / port変更でbindingが壊れるため不採用。
- Koolertron専用デバイス対応を追加する案: 将来の機材変更に弱く、OverCUEの役割を狭めるため不採用。
