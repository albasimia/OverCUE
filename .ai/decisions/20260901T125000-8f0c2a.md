# runtime targetとconfig永続化のSSOTを固定する

- Decision ID: `20260901T125000-8f0c2a`
- 日時: 2026-09-01 12:50:00 +0900
- 状態: Adopted / local verification pending

## 決定

OverCUEの`config.json`はGUIとCLIが共有する単一の永続正本とする。各processが起動時snapshotを保持すること自体は許容するが、そのsnapshot全体を後勝ちで保存してはならない。

永続更新は以下の境界で行う。

- 共通file storeがlockを取得して最新disk stateを読む。
- CLIのruntime由来更新は最新stateの対象fieldだけを変更する。
- GUIは最後に同期したbaselineとlocal stateの差分だけを最新disk stateへmergeする。
- GUI runtime controlを処理するCLIは、control適用前に最新configをreloadしてGroup / Mode / Deck / Action mappingを再解決する。

また、default Profile用GUIのruntime control targetはdefault Profileのdeviceだけから更新する。non-default Profileのstatusでdefault UI targetを置き換えない。通常の物理入力時にもdevice-scoped statusをpublishし、targetを実際の操作sourceへ追従させる。

## 理由

複数ACK05 / Logical Device / Generic HIDへ進むと、Profile、binding、mapping等をGUIとCLIが同時に参照・更新する。processごとの古い全体snapshot保存を残すと、無関係な設定変更が後勝ちで消えるため、Devices UIを追加する前に永続化の競合境界を固定する必要がある。

runtime targetについても、画面がdefault Profileを編集しているのにnon-default deviceのstatusでtargetだけが移動すると、GUIの表示対象とcontrol対象が分離する。source ProfileとUI contextを一致させる。

## 非決定

- 将来configをSQLite等へ移行するかは決めない。
- Devices UIの最終操作モデルは決めない。
- non-default ProfileをGUIから直接選択・編集する将来UIは否定しない。その場合はUI contextとruntime targetを同じLogical Device / Profileへ明示的に切り替える。
