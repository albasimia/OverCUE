# Group PresetをLogical Device→Preset参照として採用する

- Change ID: `20260902T003000-group-preset`
- 状態: 採用

## 背景

複数ACK05を同時に使う場合、各Physical Deviceのruntimeを分離するだけでは、演奏開始時の複数デバイス構成を一括で呼び出せない。一方、既存Preset自体へ別デバイスの設定を複製すると、Presetとデバイス構成の責務が混ざる。

また、各ACK05でCycle Presetした後の状態は演奏中の一時runtime stateであり、別ACK05を操作しただけで親設定の初期Presetへ戻してはならない。

## 決定

### 用語

- UI上の旧「Preset Group」は「Preset」へ統一する。
- `OverCUEPresetGroup`など既存内部型名は互換性のため当面残してよい。
- 複数Logical Deviceの組み合わせを保存する上位概念を「Group Preset」とする。

### Group Preset schema

Group Presetは以下を持つ。

- stable ID
- name
- order
- `devicePresetAssignments: [LogicalDeviceID: PresetID]`

Logical Device IDが辞書に存在することを、そのGroup Presetへデバイスを含める意味とする。値は、そのLogical Deviceが参照するProfile内のstable Preset IDとする。

Physical Deviceや接続session IDをGroup Presetへ保存しない。

### runtime

Group Presetを有効化した時、または対象Logical Deviceが新しく接続された時、そのLogical Deviceへ割り当てられたPresetを既存のdevice-scoped runtime controlで適用する。

適用後にACK05自身のCycle Presetで移動したPresetは、そのデバイスの一時runtime stateとして扱う。同じGroup Preset assignmentが変わっていない通常のruntime status / config更新では初期Presetへ巻き戻さない。

別のGroup Presetへ切り替えた場合、または現在のGroup Preset内で当該Logical DeviceのPreset assignmentを変更した場合は、新しいPresetを再適用する。

### 参照整合性

- Preset削除時、そのPresetを参照していたGroup Preset assignmentは同Profileの先頭Presetへフォールバックする。
- Logical DeviceのProfile変更時、旧ProfileのPreset IDが新Profileに存在しなければ、新Profileの先頭Presetへフォールバックする。
- Group Preset assignmentはconfigの3-way merge対象とする。
- Group Presetは最低1個を維持する。

### config version

Group Presetは現在開発中のversion 10 schemaの完成範囲として扱い、version 11へは上げない。

既存version 10 configにGroup Presetが無い場合、decode時にDefault Group Presetを補完する。version 9以前からversion 10へmigrationする場合も、migration終端で既存Logical Deviceを各Profileの先頭Presetへ割り当てたDefault Group Presetを生成する。

## 今回含めないもの

- Group Preset自体をACK05からCycleする操作。
- Group Presetから除外したデバイスのruntimeを強制停止する仕組み。
- 最初のPresetが保持しているCycle Preset mappingのglobal scope分離。
